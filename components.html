Three structural decisions are carried over exactly and are worth knowing before you touch it:

  • display: inline-grid with grid-auto-flow: column — not flex. A lone label centres optically without line-height correction.
  • A 2px transparent border is always reserved, so switching to the outline variant never moves anything.
  • Press feedback on filled variants is filter: brightness() — 0.8 on hover, 0.6 on press — so a variant needs one colour token, not three.

Checkbox · Radio · Switch · Toggle · Slider

All three selection controls separate the hit target from the drawn box: the target is one step up the space scale, so a 20px box gets a 24px target with no visual padding. The box border is 1.5px — the medium width — which is what gives these controls their weight against a dark surface.

How the API is shaped

One class, then properties

  • The class names the thing.spy-btn is a button. There is no .spy-btn--brand-sm-icon.
  • data-variant is what it meansbrand, danger, ghost, outline. Changes colour and weight, never geometry.
  • data-size is how bigChanges height, padding, icon size and type step together — never one of them alone.
  • Booleans have no valuedata-icon-only, data-full-width, data-selected, data-disabled. Present or absent.

State, and who owns it

  • The browser owns hover, active and focusNever mirrored into a data attribute — :focus-visible, not data-focused.
  • You own selected, checked, open and disabledThese outlive the pointer, so they are properties you set.
  • Loading is aria-busyBecause it is already a standard. The label hides and a spinner takes its place in the same box, so nothing reflows.
  • Error is data-invalid on the controlThe label and the message read it from there; you set it in one place.
