Four levels

Each level answers a different question, and the answer at one level is binding on the next. If a template needs something that is not in Patterns, that is a gap in Patterns — not a licence to improvise on the screen.

What spyy needs from a design system

Seven problems from the brief generate nearly all the interface. Each one is tracked through Patterns, and each pattern says which problem it serves.

Three decisions worth knowing

Places where this system departs from the current mockup, or where a detail is load-bearing and easy to lose. Each is argued from evidence in EVIDENCE.md or GAPS.md.

Confirmed

Score bars are one colour

The mockup gives each of six scores its own bar colour. The reference scoring surface makes every bar the same and puts the qualitative reading on one calibrated gradient scale. With six axes, per-bar colour makes the eye read severity where the data means difference.

See the pattern
Confirmed

Lime acts, green states

Sampling the shipped editor returned #01c317 on a checked switch — the success green, not the brand lime. The system reserves lime for actions you can take and green for state that is on. Nothing on the public site shows this.

Your call

Accent colour

The mockup uses an indigo accent; the audited brand is lime. Rather than invent a third colour, note that the reference system ships purple-600 #7152f4 and that every stateful component reads --q-tint. Re-tint and the geometry stays true.

Using it

Three stylesheets, no build

<html data-theme="dark">        <!-- or "light" -->

docs.css, shell.js and app.js belong to this reference site only. Components take one class plus data-* properties — no modifier soup: 

<button class="spy-btn" data-variant="brand" data-size="sm">Run scan</button>
<div class="spy-metric" data-pending>…</div>
<div class="spy-gauge" data-verdict="fair">…</div>

Two variables re-skin everything

  • data-themeSwaps the semantic layer. Components read semantics only, so nothing else changes.
  • --q-tintDrives switches, progress, toggles, tabs, gauges, option cards, tier pips and processing frames. Set it on any subtree to re-colour that whole region — the mechanism the reference system uses to re-skin a whole surface.

Status & known gaps

What is solid, what is a guess, and what has not been designed yet. Kept here rather than buried so nobody builds on a value that was never confirmed.

Solid

  • Every tokenTranscribed from the shipped stylesheet, then spot-checked against pixels.
  • Component geometry and statesHeights, radii, paddings, focus rings, disabled treatment — all read from source.
  • The four templatesAssembled purely from Patterns; no screen-only CSS.

Not yet

  • Light themeDerived, not confirmed. The capture set contains no light-mode product chrome.
  • Icon glyphsDrawn to the confirmed spec (24×24, 1.5 stroke, .25 grid). No third-party icon set or logomark is reproduced.
  • Campaign viewThe brief’s “output, later” — the campaign behind the videos — has no pattern yet. It is out of PoC scope.
  • Boards, saved, pattern libraryPresent in the mockup’s nav, not in the brief. Folder cards exist; the screens do not.
